# ENCpatch v0.13.43

Test build for the MA3 "multilayer encoder mapping" work: sub-page follow (0.13.42) **plus** sub-page-aware LCD-tap stack cycling (new in this release), in one installable build — the first build cut since 0.13.40, so this is the first time either fix reaches a real rig.

## Download & install

Download **ENCpatch-v0.13.43.zip** below — it contains the macOS DMG and a *Read Me First* install guide. Apple Silicon (M1 or newer) only.

The app is not notarized, so macOS will claim it is "damaged" on first launch. It isn't — run this once after copying it to Applications:

```
xattr -cr /Applications/ENCpatch.app
```

**After updating, re-import the bridge plugin in MA3** (ENCpatch → Copy bridge URL → MA3 → Menu → Plugins → + → paste; delete old ENCpatchMA3Bridge rows first). App and bridge versions must both be 0.13.43 or the app flags the bridge as outdated and skips live bar reads.

## What's new in 0.13.43

- **LCD-tap stack cycling is now sub-page aware.** Tapping an encoder's LCD cell now asks the MA3 bridge to cycle, anchored on the attribute that wheel is *actually driving right now* (live bar, sub-page included). Your configured per-feature stack lists still apply — but only when they match the slot's current attribute. Previously the desktop app cycled its config list blind: on Position page 2 a tap would snap the wheel from X Focus back to Pan.
- **Configured stacks are validated bridge-side** against the selected fixture during the cycle (one round-trip instead of the old filter → discover → set, three).
- **Instant LCD label update on tap** — the label flips with the reply instead of waiting for the next poll.
- **Regression harness committed** (`scripts/test-bridge-harness.lua`): runs the real bridge Lua against a stubbed MA3 (fake UI tree, fixture model, fake socket) — 14 checks covering sub-page follow, tick routing, user-list vs. dynamic cycling, sticky clear on page flip, and degraded-API fallbacks. Run with `texlua` or `lua5.3`.

## Carried over from 0.13.42 (never shipped in a build until now)

- Encoder bar follows sub-page position within a feature group (`resolveBarSlots()` — one source of truth for wheel ticks and LCD labels).
- Bridge diagnostics: `probeEncoderBar` (run on two pages, diff) and `setBarMode` (`auto`/`ui`/`win`/`legacy` A/B lever).
