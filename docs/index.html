Why

Stop programming movers with a mouse

Running grandMA3 onPC without a wing means clicking through encoder bars with a cursor. ENCpatch gives you back physical wheels: a Stream Deck Plus on your desk mirrors MA3's encoder bar in real time. Select a fixture and the deck's LCD strip shows exactly what MA3 shows — Pan and Tilt, Color mixing, Gobo wheels — and turning a knob drives that attribute on the console.

Change feature groups, flip sub-pages, swap fixture types: the wheels follow. No per-fixture setup, no mapping files.

Setup

Three steps to wheels

One paste into MA3, and you're turning encoders.

1

Plug in the deck

Connect a Stream Deck Plus. Quit Elgato's own Stream Deck app first — ENCpatch drives the hardware directly over USB.

2

Import the bridge plugin

Paste ENCpatch's bridge URL into grandMA3 onPC's plugin import dialog — one paste, one double-click. The status dot goes green when MA3 answers.

3

Grab a fixture, turn a wheel

The LCD strip is already showing MA3's encoder bar. Whatever the label says is what the wheel drives.

Features

What it does

Live encoder bar mirroring

The deck's 4 wheels and LCD labels track grandMA3's encoder bar automatically — feature-group changes and sub-pages included. Any fixture type, any page.

Stacked attribute cycling

Tap an encoder's LCD cell to cycle stacked attributes (Color wheel → wheel spin → shake…), with an auto-discover that reads your actual patched fixtures.

Feature-group keys

The deck's 8 buttons page between Dimmer / Position / Color / Gobo / Beam and friends, in step with the console.

ETC Eos supportBeta

Pure OSC over the network. Mirror a Custom Encoder Map (Tab 40) or pin four parameters to the wheels; Ion and Nomad key layouts included.

Open OSC, in and out

TouchOSC, fader wings, and Bitfocus Companion can drive ENCpatch's mappings too.

Local web UI, no cloud

Mappings, encoder stacks, console choice, and live diagnostics at 127.0.0.1:8733. Nothing leaves your machine. Free and open source, MIT-licensed.

Requirements

What you need

  • Apple Silicon Mac (M1 or newer). Intel Macs and Windows are not supported.
  • grandMA3 onPC 2.0 or newer on the same Mac — or an Eos-family console / Nomad on the network with OSC enabled (TX port 8002).
  • Elgato Stream Deck Plus recommended. Other Stream Decks work for buttons only — the encoders are the point.
  • Elgato's Stream Deck app must be quit while ENCpatch runs — the deck is driven directly over USB.
Install

Two minutes, one Terminal line

Read this first — the "damaged" warning

ENCpatch is independently developed and not App Store-signed, so macOS shows a false "ENCpatch is damaged and can't be opened" warning on first launch. The app is fine — that's Gatekeeper reacting to an unsigned indie app. After copying it to Applications, run this once in Terminal, then open it normally:

$ xattr -cr /Applications/ENCpatch.app

You only do this once per install.

  1. Open the .dmg and drag the ENCpatch icon onto the Applications shortcut.
  2. Eject the .dmg and run the xattr command above.
  3. Open ENCpatch. Grant the Input Monitoring permission macOS asks for (that's how it talks to the Stream Deck), then re-open the app.
  4. Follow the 3-step welcome screen: deck → bridge plugin → preset. Done.

Full walkthrough, Eos setup, and troubleshooting: see the install guide.

FAQ

Questions

What does it cost?
Nothing. ENCpatch is free and open source, MIT-licensed.
Does it work on Windows?
No — macOS on Apple Silicon only, for now.
Do I need a Stream Deck Plus specifically?
For the encoders, yes — that's the whole point. Regular Stream Decks can still run the button/key layouts.
Does it work with a real grandMA3 console?
It's built and tested against grandMA3 onPC on the same Mac. The bridge plugin can bind to a LAN address with a token for remote setups, but console-hardware workflows aren't the target.
Why does macOS say the app is damaged?
It isn't — that's Gatekeeper reacting to an unsigned indie app. The one-line xattr -cr /Applications/ENCpatch.app command fixes it permanently.
Is my show data sent anywhere?
No. Everything runs locally: USB to the deck, localhost TCP to MA3, LAN OSC to Eos. No accounts, no telemetry.
